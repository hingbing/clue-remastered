# 로스트시티 온라인 2인 대전 설계

## 목표

현재 Vercel 클라이언트와 Render 서버로 운영 중인 보드게임 허브에 로스트시티 방식의 온라인 2인 대전을 추가한다. 한 플레이어가 방을 만들고 코드를 친구에게 전달하면, 두 사람이 서로 다른 장소에서도 게임할 수 있어야 한다.

기존 클루와 아브라카왓의 게임 로직 및 UI는 수정하지 않는다. 메인 게임 선택 화면과 서버 등록부만 최소한으로 변경하고, 로스트시티 코드는 별도 모듈로 추가한다.

## 확정 범위

- 로그인 없는 닉네임 기반 2인 방
- 방 생성, 코드 참가, 자동 재접속, 방 나가기
- 서버가 판정하는 실시간 Socket.IO 게임
- 노랑, 흰색, 파랑, 초록, 빨강, 보라의 6색 필드
- 색상별 숫자 2~10 카드 9장과 X2 투자 카드 3장
- 색상별 12장, 전체 72장
- 8장씩 초기 손패
- PC 및 스마트폰 가로 화면 완전 지원
- 빈티지 탐험책 스타일의 독자적인 이미지 자산
- 게임 종료 후 색상별 세부 점수와 승자 표시

다음 항목은 범위에 포함하지 않는다.

- 로그인 및 계정
- 관전자
- 매치메이킹
- 채팅
- 서버 재시작 이후 게임 복원
- 카드 상세 확대 또는 길게 누르기
- 기존 클루 및 아브라카왓 내부 리팩터링

## 통합 구조

### 클라이언트

`client/src/LostCitiesGame.tsx`를 새로 추가한다. 로스트시티의 대기실, 게임판, 손패, 결과 화면과 Socket.IO 연결은 이 컴포넌트가 소유한다.

`client/src/App.tsx`에는 `lost-cities` 게임 타입, 선택 버튼, `LostCitiesGame` 렌더링 분기만 추가한다. `ClueGame.tsx`와 `AbracaWhatGame.tsx`는 수정하지 않는다.

로스트시티 스타일은 기존 스타일에 영향을 주지 않도록 `lostCities` 접두사를 사용한다. 이미지 자산은 `client/public/lost-cities/` 아래에 둔다.

### 서버

`server/src/lostCities.ts`를 새로 추가하고 Socket.IO 서버를 받는 등록 함수를 제공한다. 방 생성, 참가, 재접속, 카드 생성과 셔플, 턴 판정, 종료, 점수 계산은 모두 이 모듈에 둔다.

서버 시작 파일은 로스트시티 등록 함수를 호출하는 연결부만 변경한다. 기존 클루 이벤트 및 아브라카왓 등록 로직은 변경하지 않는다.

모든 이벤트는 `lost-cities:*` 네임스페이스를 사용한다. 예시는 다음과 같다.

- `lost-cities:room:create`
- `lost-cities:room:join`
- `lost-cities:room:rejoin`
- `lost-cities:room:leave`
- `lost-cities:game:start`
- `lost-cities:card:play`
- `lost-cities:card:draw`
- `lost-cities:room:state`
- `lost-cities:error`

### 공유 타입

로스트시티 카드, 색상, 공개 플레이어, 공개 방 상태 타입을 전용 공유 파일에 둔다. 서버 내부 상태와 클라이언트 공개 상태는 분리한다.

상대방에게 보내는 공개 상태에는 상대 손패의 장수만 포함한다. 카드 ID, 색상, 숫자, X2 여부는 소유 플레이어에게만 보낸다. 서버는 소켓별로 상태를 직렬화해 전송한다.

## 게임 데이터

### 카드

색상은 `yellow`, `white`, `blue`, `green`, `red`, `purple` 여섯 종류다.

각 색상에는 다음 카드가 있다.

- 숫자 카드 2~10: 각 1장
- X2 투자 카드: 3장

각 카드는 서버 판정을 위한 고유 ID를 가진다. 같은 색의 X2 세 장은 같은 앞면 이미지를 사용하지만 ID는 서로 다르다.

### 방 상태

서버 내부 방 상태에는 최소한 다음 정보를 유지한다.

- 방 코드와 상태: 대기, 진행, 종료
- 플레이어 두 명과 방장 여부, 연결 상태
- 각 플레이어의 비공개 손패
- 각 플레이어가 색상별로 내려놓은 탐험 카드
- 색상별 버림 더미
- 중앙 탐험 덱
- 현재 플레이어
- 현재 턴 단계: 카드 내기 또는 카드 받기
- 현재 턴에 버린 카드 ID
- 최근 행동
- 종료 점수와 승자 ID 목록

## 방과 연결 흐름

한 플레이어가 닉네임을 입력하고 방을 만들면 짧은 대문자 방 코드를 받는다. 친구는 닉네임과 코드를 입력해 참가한다. 방에는 최대 2명만 들어갈 수 있다.

방장만 게임을 시작할 수 있으며, 정확히 2명이 연결된 상태에서만 시작 요청을 허용한다. 시작 시 72장을 셔플하고 각 플레이어에게 8장씩 배분한다. 중앙 덱에는 56장이 남는다. 시작 플레이어는 무작위로 정한다.

클라이언트는 게임별로 분리된 세션 저장소 키에 방 코드와 플레이어 ID를 보관한다. 새로고침 또는 일시적인 연결 끊김 뒤에는 이 값으로 재접속한다. 연결이 끊긴 플레이어는 방에 남고 상대 화면에는 연결 끊김 상태가 표시된다.

플레이어가 명시적으로 방을 나가면 진행 중 게임은 중단하고 남은 플레이어에게 안내한다. 서버 프로세스 재시작 시 메모리 방이 사라지는 동작은 기존 게임과 동일하게 유지한다.

## 턴 흐름과 판정

한 턴은 반드시 두 단계로 진행한다.

### 1. 카드 내기

현재 플레이어는 손패 한 장을 골라 다음 중 하나를 수행한다.

- 같은 색의 자기 탐험 구역에 놓는다.
- 같은 색의 중앙 버림 더미에 버린다.

탐험 구역에는 다음 제한을 적용한다.

- X2 카드는 숫자 카드보다 먼저 놓아야 한다.
- 숫자 카드가 한 장이라도 놓인 색상에는 X2를 놓을 수 없다.
- 숫자 카드는 이미 놓인 마지막 숫자보다 커야 한다.

성공적으로 카드를 내면 턴 단계는 카드 받기로 바뀐다. 버린 경우 서버는 그 카드 ID를 현재 턴의 버린 카드로 기록한다.

### 2. 카드 받기

현재 플레이어는 다음 중 하나에서 맨 위 카드 한 장을 받는다.

- 중앙 탐험 덱
- 여섯 색상 중 비어 있지 않은 버림 더미

현재 턴에 자신이 방금 버린 카드와 ID가 같은 카드는 다시 받을 수 없다. 빈 버림 더미에서는 받을 수 없다.

카드를 정상적으로 받으면 손패는 다시 8장이 되고 상대에게 턴이 넘어간다. 중앙 덱의 마지막 카드를 받은 경우에는 턴을 넘기지 않고 즉시 게임을 종료한다.

클라이언트는 가능한 행동만 강조하지만, 최종 검증과 상태 변경은 항상 서버가 담당한다.

## 점수 계산

색상별 점수는 다음 순서로 계산한다.

1. 해당 색상에 카드가 없으면 0점이다.
2. 숫자 카드의 합에서 20을 뺀다.
3. 결과에 `X2 카드 수 + 1`을 곱한다.
4. X2를 포함해 해당 색상에 카드가 8장 이상이면 20점을 더한다.

따라서 배수는 X2가 0장이면 1배, 1장이면 2배, 2장이면 3배, 3장이면 4배다. 여섯 색상 점수를 합산해 총점을 계산한다. 총점이 높은 플레이어가 승리하며 동점이면 공동 승리로 처리한다.

결과 화면은 각 색상의 숫자 합, 기본 비용, X2 배수, 8장 보너스, 최종 색상 점수와 총점을 보여준다.

## 화면 설계

### 메인 화면과 대기실

메인 화면에 클루, 아브라카왓, 로스트시티 선택지를 표시한다. 로스트시티 대기실은 기존 게임과 같은 닉네임, 방 만들기, 방 코드 참가 흐름을 사용한다.

### 미술 방향

전체 디자인은 양피지, 손그림 지도, 오래된 탐험 기록을 연상시키는 빈티지 탐험책 스타일을 사용한다. 기존 상용 게임 이미지를 복제하지 않고 독자적인 자산을 사용한다.

색상별 탐험지는 다음과 같다.

- 노랑: 황금 사원
- 흰색: 설산 유적
- 파랑: 침몰 도시
- 초록: 밀림 신전
- 빨강: 화산 요새
- 보라: 달빛 묘지

### 게임판

가로형 게임판은 세 영역으로 나눈다.

- 위쪽: 상대방의 색상별 탐험 카드
- 중앙: 여섯 탐험지 필드와 색상별 버림 더미
- 아래쪽: 내 색상별 탐험 카드와 손패

중앙 필드에 버린 카드가 없으면 해당 탐험지 기본 이미지를 표시한다. 카드가 있으면 탐험지 이미지 위에 버림 더미의 맨 위 카드 이미지를 표시하고, 작은 배지로 더미의 총 장수를 보여준다.

카드를 누르면 선택 상태를 표시하고 가능한 탐험 또는 버리기 동작만 활성화한다. 카드를 낸 뒤에는 중앙 덱과 선택 가능한 버림 더미를 강조한다. 현재 턴 단계와 오류는 화면에서 분명하게 표시한다.

### 반응형 동작

PC에서는 여섯 색상과 양쪽 탐험, 손패를 한 화면에 표시한다.

스마트폰은 가로 모드를 기준으로 같은 정보 구조를 유지한다. 세로 모드에서는 기기를 가로로 돌리라는 안내 화면을 표시한다. 가로 화면에서는 다음을 적용한다.

- 상대 탐험은 위쪽
- 탐험지 이미지와 버림 카드 이미지는 중앙
- 내 탐험은 중앙 아래쪽
- 손패 8장은 화면 하단 고정
- 중앙 덱 수량, 턴 단계, 예상 점수, 최근 행동은 가장자리의 압축 패널
- 터치 가능한 조작 요소는 최소 44px

카드 상세 확대 기능은 제공하지 않는다.

## 이미지 자산

앞면 카드는 총 60종의 고유 이미지를 사용한다.

- 숫자 2~10 × 6색: 54종
- X2 × 6색: 6종

같은 색의 X2 세 장은 동일 이미지를 재사용한다. 추가로 공용 카드 뒷면 1종과 중앙 필드용 탐험지 이미지 6종을 제작한다.

모든 카드 이미지는 동일한 비율과 안전 여백을 사용하고, 작은 화면에서도 숫자 또는 X2와 색상을 식별할 수 있어야 한다. 파일 이름은 카드 데이터에서 결정적으로 계산할 수 있게 구성한다.

## 오류 처리

서버가 거절해야 하는 대표 요청은 다음과 같다.

- 정원이 찬 방 참가
- 존재하지 않거나 종료된 방 참가
- 방장이 아닌 플레이어의 게임 시작
- 두 명이 모이기 전 게임 시작
- 자기 차례가 아닌 행동
- 현재 턴 단계에 맞지 않는 행동
- 손패에 없는 카드 사용
- 잘못된 색상 탐험에 카드 놓기
- 숫자 카드 이후 X2 놓기
- 오름차순을 위반한 숫자 놓기
- 빈 버림 더미에서 카드 받기
- 방금 버린 카드 다시 받기

거절된 요청은 방 상태를 변경하지 않는다. 요청한 플레이어에게만 이해하기 쉬운 오류 메시지를 보내고, 클라이언트는 잠시 보이는 토스트로 표시한다.

## 테스트와 완료 기준

규칙 로직은 Socket.IO 처리와 분리된 순수 함수로 구성해 다음 항목을 자동 검증한다.

- 72장 덱과 색상별 12장 구성
- 8장씩 배분 후 중앙 덱 56장
- X2 선행 규칙
- 숫자 오름차순 규칙
- 카드 내기와 카드 받기의 2단계 턴
- 방금 버린 카드 재수령 차단
- 마지막 중앙 덱 카드 수령 직후 종료
- 빈 탐험 0점
- 기본 비용 20점
- X2 0~3장의 1~4배 계산
- X2 포함 8장 이상 보너스 20점
- 총점과 공동 승리

온라인 상태 검증은 다음 항목을 포함한다.

- 방 생성, 코드 참가, 정원 제한
- 방장 시작 권한
- 자동 재접속과 연결 상태
- 명시적 방 나가기
- 상대에게 손패 내용이 노출되지 않음
- 잘못된 요청이 상태를 변경하지 않음

UI 및 회귀 검증은 다음 항목을 포함한다.

- PC 가로 화면
- 스마트폰 가로 화면
- 스마트폰 세로 회전 안내
- 중앙 필드 기본 이미지와 버린 카드 이미지 전환
- client 및 server 전체 빌드
- 클루와 아브라카왓의 기존 진입 및 빌드 유지

완료 조건은 두 브라우저가 방 코드로 같은 방에 접속해 전체 게임을 끝까지 진행하고, 서버가 계산한 결과를 양쪽에서 동일하게 확인할 수 있는 것이다.
